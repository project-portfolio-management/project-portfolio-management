# 독립 보안 테스트

*구매자, 평가자, 테스터를 위해: 이 소프트웨어의 독립 보안 테스트가 다뤄야 할 것, 프로젝트가 돕기 위해 제공하는 것, 이루어진 것과 이루어지지 않은 것, 그리고 직접 맡아야 하는 것. 이 문서는 안내이며 테스트 보고서도 법률 자문도 아닙니다.*

## 현재 상태

**독립 보안 테스트는 수행되지 않았습니다.** 이 소프트웨어에는 침투 테스트, 제3자 감사, 독립 코드 검토, 인증이 없으며 프로젝트도 그런 것을 주장하지 않습니다([운영 환경으로 가는 길](../../path-to-production/index.md), [SECURITY](../../../../SECURITY.md)). 프로젝트의 지속적 통합에서는 수동적 스캔이 실행되고(규칙은 `.zap/rules.tsv`에 있음), 프로젝트 자체 테스트가 아래에 나열된 통제를 확인합니다. 둘 다 소프트웨어를 작성하지 않은 테스터를 대신하지 못합니다.

이는 [보증 체크리스트](../../../../governance/assurance-checklist.md)의 1번과 9번 항목입니다. 공인 테스터가 **여러분의** 배포를 대상으로 수행하는 것으로 배포자의 몫입니다. 프로젝트는 여러분의 호스팅, ID 공급자, 네트워크, 키를 테스트할 수 없습니다.

## 무엇을 테스트할까

로그인이 강제되고 ID 공급자가 앞단에 있는, 실제로 운영될 모습 그대로 배포를 테스트하세요. 소프트웨어가 주장하는 통제를 바탕으로 한 권장 범위는 다음과 같습니다.

| 영역 | 소프트웨어가 주장하는 것 | 테스터가 시도해 볼 것 |
|---|---|---|
| 인증 | 로그인은 기본으로 켜져 있음. 서비스는 검증 키가 없으면, 그리고 운영 환경에서 로그인이 꺼져 있으면 시작하지 않음. 토큰은 공개된 키로 오프라인 검증됨 | 위조, 만료, 재전송, 잘못 서명된 토큰. 잘못된 발급자나 대상. 키 교체. 키 세트 누락 |
| 권한 부여 | 속성 기반 정책. 레코드 수준 규칙 | 모든 경로에서의 수평·수직 권한 상승. 경로와 본문의 식별자 변경. 호출자가 추가할 수 없어야 하는 속성 |
| 비공개 계획과 취급 표시 | 비공개 계획과 호출자의 허가 수준을 넘는 계획은 관리자까지 포함해 해당 호출자의 어떤 목록, 개수, 합계, 검색 결과, 피드, 내보내기에도 없음 | 호출자가 읽을 수 없는 계획의 존재, 이름, 개수, 합계를 흘리는 모든 경로. "숨김"과 "없음"에서 다르게 나타나는 오류 메시지와 응답 시간 |
| 긴급 접근 | 자격이 있는 사람만, 명시된 사유, 최대 네 시간, 두 번째 사람에게 알림 | 자격 없이 사용. 권한 연장. 두 번째 사람에게 알리지 않고 행동 |
| 고정된 기록과 추가 전용 기록 | 감사 추적, 발행된 이사 패킷, 수행 신뢰도 이력, 프로그램 상태 이력, 프로젝트 버퍼는 데이터베이스에서 변경과 삭제를 거부함 | API, 대량 가져오기, 같은 행을 건드리는 모든 경로를 통한 갱신이나 삭제 |
| 직무 분리 | 요청자는 자신의 변경 요청을 승인할 수 없음 | 요청자로서, 관리자로서, 제출 후 승인자를 바꾸는 방식으로 승인 |
| 업로드와 첨부 파일 | 내용은 선언된 유형과 일치해야 함. 프로그램은 거부됨. 선택 사항인 바이러스 검사 연결 지점은 실패 시 차단 | 폴리글롯 파일, 이름을 바꾼 프로그램, 지나치게 크거나 형식이 잘못된 파일, 이름에 넣은 경로 조작, 검사기가 실제로 호출되는지 여부 |
| 외부로 나가는 요청 | 사용자가 지정한 대상은 공개 `https` 주소로 제한됨 | 사설, 링크 로컬, 메타데이터 주소로의 서버 측 요청 위조. 리디렉션. DNS 리바인딩 |
| 세션과 브라우저 | 유휴 만료, 절대 한도, `httpOnly` 쿠키, 엄격한 콘텐츠 보안 정책, CORS 허용 목록 | 세션 고정과 재사용, 사이트 간 요청 위조, 인터페이스로의 주입, 클릭재킹 |
| 요청 속도 제한 | 호출자별 한도 | ID, 헤더, 경로를 바꿔 우회. 프록시를 거쳐도 한도가 유지되는지 |
| 정보 주체 도구 | 내보내기와 가명 처리. 관리자 전용, 미리 보기 먼저 | 관리자가 아닌 사람의 사용. [개인정보 목록](../../../../governance/personal-data-inventory.csv)에 대한 완전성 |
| 백업 | 선택적 암호화, 검증된 복원 | 백업 파일과 키에 대한 접근. 깨끗한 환경으로 복원 |

## 프로젝트가 제공하는 것

- 소스, 명세, 테스트. 코드 검토를 주장에서 출발해 시작할 수 있습니다.
- API의 기계 판독 가능한 설명(`/api-docs/openapi.json`). 이사 패킷 작업의 요청과 응답 스키마가 있으며, 경로 목록은 테스트로 코드와 대조됩니다.
- 로그인이 꺼진 일회용 설정(`dev-insecure`, [README](../../../../README.md) 참고). **테스터 자신의 기계에서만** 사용하세요. 그리고 테스트 키 세트를 만드는 스크립트(`scripts/smoke-keys.sh`)로, 원하는 속성을 가진 토큰을 테스트 배포에 대해 발급할 수 있습니다.
- [데이터 흐름도](../../../../governance/data-flow.md), [운영 지침서](../../../../operations/runbook.md), [복구 목표](../../../../operations/recovery-objectives.md).
- 발견한 것을 비공개로 신고하는 방법: [SECURITY.md](../../../../SECURITY.md).

## 교전 규칙

어떤 테스트든 시작 전에 서면으로 합의하세요. 프로젝트가 여러분의 환경에 대해 이를 정해 줄 수는 없습니다.

- **환경.** 현실적이지만 실제는 아닌 데이터가 든 사본을 테스트하세요. 서면으로 결정한 경우가 아니라면 운영 환경을 테스트하지 마세요.
- **권한.** 테스터는 서면 허가, 지정된 연락 담당자, 명시된 시간대를 가집니다.
- **범위 밖.** 물량에 의한 서비스 거부, 직원 대상 사회공학, 제3자 서비스(ID 공급자, 호스팅)는 각 소유자가 동의하지 않는 한 범위 밖입니다. 프로젝트 자체의 범위는 [SECURITY](../../../../SECURITY.md)에 있습니다.
- **데이터.** 실제 개인정보는 사용하지 않고, 밖으로 복사하지 않으며, 보고서에 넣지 않습니다.
- **키.** 테스트 키는 운영 키와 분리하며 끝난 뒤 파기합니다.

## 보고와 재테스트

- 이 소프트웨어에 대한 발견은 [SECURITY](../../../../SECURITY.md)에 따라 유지 관리자에게 비공개로 보내며, 재현 방법, 버전 또는 커밋, 영향을 함께 적습니다. 프로젝트의 목표는 영업일 5일 이내 접수 확인과 15일 이내 계획 제시이며, 목표일 뿐 보장은 아닙니다. 유지 관리자는 한 명이고 서비스 수준 계약은 없습니다.
- 여러분의 배포에 대한 발견은 여러분 쪽 소유자에게 보냅니다.
- 테스터에게 발견마다 등급을 매기고, **테스트하지 않은** 것이 무엇인지 밝히고, 수정 사항을 재테스트해 달라고 요청하세요. 발견한 것만 나열한 보고서는 놓친 것을 알려 주지 않습니다.
- 보고서, 범위, 날짜, 재테스트를 자체 기록과 함께 보관하세요. 프로젝트가 대신 보관해 줄 수 없습니다.

## 이 문서의 한계

다뤄야 할 영역을 나열한 것이지 완전한 테스트 계획이 아니며, 표의 주장은 프로젝트 자체의 것입니다. 아무것도 인증하지 않으며, 깨끗한 테스트 결과는 특정 날짜의 한 배포에 대한 증거일 뿐입니다.

## 직접 내려야 할 결정

누가, 언제, 무엇을 대상으로, 어떤 데이터로, 어떤 규칙 아래 테스트하는지. 발견을 어떻게 등급화하고 언제까지 고쳐야 하는지. 결과를 평가자에게 공유할지 여부.
