# 最高リスク責任者（CRO）向け

*最高リスク責任者: ソフトウェアが見えるようにするリスクと、使うことのリスク。*

## 管理を支えるリスク

- **リスク、課題、変更要求**は計画ごとに記録されます。読み取り可能な計画をまたぐ課題登録簿があり、変更要求には職務分掌があります。
- **実行の確信度と例外:** 述べられた確信度は算出された RAG とは別に保持され、二段階以上食い違うとフラグが立ちます。履歴は追記専用で、48 時間の例外の時計は、評価が悪化しても再開されず、記録された判断によってのみ閉じられます。
- **欠如の正直な扱い:** 欠けているデータは、緑やゼロではなく、「未評価」または理由付きの null として表示されます。
- **凍結され、版管理された月次パック。**ディレクターに伝えた内容を、後から発行時のとおりに示せます。

## 使うことのリスク（プロジェクト自身の登録簿）

| リスク | 状態 |
|---|---|
| ペネトレーションテスト、第三者監査、認証がない | 未対応: 購入者が依頼します（[保証チェックリスト](../../../../governance/assurance-checklist.md)） |
| 保持が一部のデータにしか強制されない | 未対応。パージをスケジュールする必要があります |
| データ主体ツールが自由記述、添付ファイル、バックアップを検索しない | 未対応 |
| 監査証跡はデータベース管理者に破られうる。ハッシュチェーンなし | [DPIA](../../../../governance/dpia.md) に明記 |
| 取り扱い区分は隠してラベルを付けるが、暗号化はしない | 明記済み |
| 添付ファイルのスキャンには、導入者が運用するスキャナーが必要 | 未対応 |
| メンテナーは一人で、SLA なし | 未対応 |
| 翻訳は草稿 | 未対応 |
| 非臨床のみ。臨床安全性ケースなし | 臨床的な内容を入力しないでください |

## ソフトウェアが強制する統制

初期状態で有効なログイン、レート制限、厳格なセキュリティヘッダー、アイドルセッションのタイムアウト（30 分）と絶対的なセッション上限、公開 `https` に限定した送信先、署名を検査する添付ファイル、不変の監査行、監査付きのブレークグラス。それぞれは、[本番への道筋](../../path-to-production/index.md)に挙げたテストで確認されています。

## あなたが決めること

パイロットのリスク許容度、例外の期間（既定は 48 時間）、この導入が保証を受ける区分レベル、誰がアクセス一覧をどのくらいの頻度でレビューするか。
