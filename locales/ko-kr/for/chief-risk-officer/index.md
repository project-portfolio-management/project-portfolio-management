# 최고위험책임자(CRO)를 위한 안내

*최고위험책임자: 소프트웨어가 파악하도록 돕는 위험, 그리고 소프트웨어를 쓰는 데 따르는 위험.*

## 관리하도록 돕는 위험

- 계획마다 기록되는 **위험, 이슈, 변경 요청.** 열람할 수 있는 계획 전반의 이슈 등록부. 직무 분리가 적용되는 변경 요청.
- **수행 신뢰도와 예외:** 밝힌 신뢰도는 계산된 RAG와 따로 유지되고, 두 단계 이상 벌어지면 표시되며, 추가만 가능한 이력이 있습니다. 48시간 예외 시계는 등급이 나빠져도 다시 시작되지 않고 기록된 결정으로만 닫힙니다.
- **정직한 부재:** 빠진 데이터는 녹색이나 0이 아니라 이유와 함께 "평가되지 않음" 또는 null로 나타납니다.
- **고정되고 버전이 있는 월간 패킷.** 이사들에게 전달된 내용을 나중에 발행된 그대로 보여 줄 수 있습니다.

## 사용에 따르는 위험 (프로젝트 자체 등록부)

| 위험 | 상태 |
|---|---|
| 침투 테스트, 제3자 감사, 인증 없음 | 열림: 구매자가 의뢰해야 함 ([보증 체크리스트](../../../../governance/assurance-checklist.md)) |
| 데이터 일부에 대해서만 보존 시행 | 열림. 삭제 작업을 예약해야 함 |
| 정보 주체 도구가 자유 텍스트, 첨부 파일, 백업을 검색하지 않음 | 열림 |
| 데이터베이스 관리자가 감사 추적을 무력화할 수 있음. 해시 체인 없음 | [DPIA](../../../../governance/dpia.md)에 명시 |
| 취급 표시는 숨기고 표시할 뿐 암호화하지 않음 | 명시 |
| 첨부 파일 검사에는 배포자가 운영하는 검사기가 필요 | 열림 |
| 유지 관리자 한 명, SLA 없음 | 열림 |
| 번역은 초안 | 열림 |
| 비임상 전용. 임상 안전 사례 없음 | 임상 내용을 입력하지 마세요 |

## 소프트웨어가 시행하는 통제

기본 로그인, 요청 속도 제한, 엄격한 보안 헤더, 유휴 세션 만료(30분)와 절대 세션 한도, 공개 `https`로 제한된 외부 대상, 서명을 확인하는 첨부 파일, 변경할 수 없는 감사 행, 감사가 따르는 긴급 접근. 각각 [운영 환경으로 가는 길](../../path-to-production/index.md)에 인용된 테스트로 확인됩니다.

## 직접 내려야 할 결정

시범 운영에 대한 위험 선호, 예외 기간(기본 48시간), 배포가 보증받은 표시 수준, 접근 목록을 누가 얼마나 자주 검토하는지.
