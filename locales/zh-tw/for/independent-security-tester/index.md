# 獨立安全測試

*寫給買方、評估人員或測試人員：對本軟體進行獨立安全測試應涵蓋什麼、專案提供哪些幫助、哪些已做哪些未做，以及哪些留給您。這是指導，不是測試報告，也不是法律意見。*

## 現狀

**尚未進行任何獨立安全測試。** 本軟體沒有滲透測試、第三方審計、獨立程式碼評審或認證，專案也不聲稱有（[通往生產之路](../../path-to-production/index.md)、[SECURITY](../../../../SECURITY.md)）。專案的持續整合中執行被動掃描（規則在 `.zap/rules.tsv`），專案自己的測試檢查下文列出的控制；二者都不能代替一位沒有編寫過這個軟體的測試人員。

這是[保證清單](../../../../governance/assurance-checklist.md)的第 1 項和第 9 項。它屬於部署方，由持證測試人員針對**您的**部署進行：專案無法測試您的託管、身份提供方、網路或金鑰。

## 測試什麼

按實際執行的方式測試部署，強制登入，並讓您的身份提供方位於前端。根據軟體所聲稱的控制，建議的範圍如下：

| 領域 | 軟體聲稱的 | 測試人員應嘗試的 |
|---|---|---|
| 認證 | 預設啟用登入；沒有驗證金鑰服務不會啟動，在生產環境中關閉登入也不會啟動；令牌用公佈的金鑰離線驗證 | 偽造、過期、重放和簽名錯誤的令牌；錯誤的簽發者或受眾；金鑰輪換；缺失金鑰集 |
| 授權 | 基於屬性的策略；記錄級規則 | 每個路由上的橫向和縱向越權；更改路徑和請求體中的識別符號；呼叫者不應能新增的屬性 |
| 私有計劃與處理標記 | 私有計劃以及高於呼叫者許可級別的計劃，不出現在該呼叫者的任何列表、計數、合計、搜尋結果、訂閱源或匯出中，管理員也不例外 | 任何洩露呼叫者無權讀取的計劃的存在、名稱、計數或合計的路由；「被隱藏」與「不存在」之間不同的錯誤資訊和響應時間 |
| 緊急通道 | 僅限符合資格者、陳述理由、最長四小時、通知第二個人 | 無資格使用；延長授權；未通知第二個人就行動 |
| 凍結與只追加的記錄 | 審計記錄、已簽發的董事簡報包、交付信心歷史、專案集狀態歷史和專案緩衝在資料庫中拒絕更改和刪除 | 透過 API、批次匯入以及任何涉及同一行的路由進行更新或刪除 |
| 職責分離 | 請求者不能批准自己的變更請求 | 以請求者身份、以管理員身份批准，以及提交後更換批准人 |
| 上傳與附件 | 內容必須與宣告的型別一致；程式被拒絕；可選的病毒掃描鉤子在失敗時拒絕放行 | 多語言混合檔案、改名的程式、超大和畸形檔案、名稱中的路徑技巧，以及您的掃描器是否真被呼叫 |
| 出站請求 | 使用者提供的目的地僅限公共 `https` 地址 | 對私有、鏈路本地和後設資料地址的服務端請求偽造、重定向、DNS 重繫結 |
| 會話與瀏覽器 | 空閒超時、硬性上限、`httpOnly` Cookie、嚴格的內容安全策略、CORS 允許列表 | 會話固定與重用、跨站請求偽造、向介面注入、點選劫持 |
| 速率限制 | 按呼叫者限制 | 透過更改身份、標頭或路徑繞過；限制能否在您的代理之後依然有效 |
| 資料主體工具 | 匯出與假名化，僅限管理員，先預覽 | 非管理員使用；對照[個人資料清單](../../../../governance/personal-data-inventory.csv)檢查完整性 |
| 備份 | 可選加密，經過測試的恢復 | 訪問備份檔案和金鑰；恢復到乾淨的環境 |

## 專案提供什麼

- 原始碼、規範和測試，使程式碼評審可以從這些宣告出發。
- 機器可讀的 API 描述（`/api-docs/openapi.json`），包含董事簡報包相關工作的請求與響應模式；路由列表由測試與程式碼核對。
- 登入關閉的一次性配置（`dev-insecure`，見 [README](../../../../README.md)），**僅限測試人員自己的機器**，以及一個生成測試金鑰集的指令碼（`scripts/smoke-keys.sh`），以便針對測試部署簽發帶指定屬性的令牌。
- [資料流圖](../../../../governance/data-flow.md)、[執行手冊](../../../../operations/runbook.md)和[恢復目標](../../../../operations/recovery-objectives.md)。
- 報告發現的私下渠道：[SECURITY.md](../../../../SECURITY.md)。

## 交戰規則

測試前以書面形式商定這些；專案無法為您的環境設定它們。

- **環境。** 測試一份副本，使用逼真但非真實的資料。除非您已書面決定，否則不要測試生產環境。
- **授權。** 測試人員持有您的書面許可、一位指定聯絡人和明確的時間視窗。
- **範圍之外。** 靠流量的拒絕服務、對員工的社會工程學以及第三方服務（您的身份提供方、您的主機）不在範圍內，除非各自的所有者同意。專案自身的範圍見 [SECURITY](../../../../SECURITY.md)。
- **資料。** 不使用真實個人資料，不將其複製出去，也不寫入報告。
- **金鑰。** 測試金鑰與生產金鑰分開，並在事後銷燬。

## 報告與複測

- 關於本軟體的發現應按 [SECURITY](../../../../SECURITY.md) 所述私下提交給維護者，附上覆現方法、版本或提交以及影響。專案的目標是 5 個工作日內確認、15 個工作日內給出計劃；這是目標，不是保證。只有一位維護者，沒有服務水平協議。
- 關於您的部署的發現交給您自己的負責人。
- 請測試人員對每項發現評級，說明**未**測試的內容，並對修復進行復測。只列出發現內容的報告無法告訴您遺漏了什麼。
- 將報告、範圍、日期和複測與您自己的記錄一起儲存。專案無法替您儲存。

## 本文件的侷限

它列出需要涵蓋的領域，不是完整的測試計劃，表中的宣告是專案自己的。它不證明任何事情，一次乾淨的測試只是關於某一部署在某一日期的證據。

## 屬於您的決定

誰來測試、何時、針對什麼、用什麼資料、在什麼規則下；如何給發現評級、必須在何時之前修復；以及結果是否與您的評估人員共享。
