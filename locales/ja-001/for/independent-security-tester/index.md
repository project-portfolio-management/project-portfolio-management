# 独立したセキュリティテスト

*購入者、評価者、テスト担当者のために: このソフトウェアの独立したセキュリティテストが何を対象とすべきか、プロジェクトが何を提供するか、何が行われ何が行われていないか、そして何があなたに委ねられているか。これは指針であり、テスト報告書でも法的助言でもありません。*

## 現状

**独立したセキュリティテストは行われていません。**このソフトウェアには、ペネトレーションテスト、第三者監査、独立したコードレビュー、認証のいずれも存在せず、プロジェクトもそれらを主張しません（[本番への道筋](../../path-to-production/index.md)、[SECURITY](../../../../SECURITY.md)）。プロジェクトの継続的インテグレーションではパッシブスキャンが実行され（ルールは `.zap/rules.tsv`）、プロジェクト自身のテストが以下に挙げる統制を確認しますが、どちらも、ソフトウェアを書いていないテスト担当者の代わりにはなりません。

これは[保証チェックリスト](../../../../governance/assurance-checklist.md)の項目 1 と項目 9 です。認定を受けたテスト担当者が**あなたの**導入に対して行うもので、導入者の責務です。プロジェクトは、あなたのホスティング、アイデンティティプロバイダー、ネットワーク、鍵をテストできません。

## 何をテストするか

ログインを強制し、アイデンティティプロバイダーを手前に置いた、実際に動かす形の導入をテストしてください。ソフトウェアが主張する統制に基づく、推奨の範囲は次のとおりです。

| 領域 | ソフトウェアの主張 | テスト担当者が試すこと |
|---|---|---|
| 認証 | ログインは初期状態で有効。検証キーがなければ、また本番でログインが無効なら、サービスは起動しない。トークンは公開された鍵に対してオフラインで検証される | 偽造、期限切れ、再送、誤った署名のトークン。誤った発行者や対象者。鍵のローテーション。鍵セットの欠如 |
| 認可 | 属性ベースのポリシー。レコード単位のルール | すべてのルートでの水平および垂直の権限昇格。パスと本文内の識別子の変更。呼び出し元が追加できてはならない属性 |
| 非公開の計画と取り扱い区分 | 非公開の計画と、呼び出し元のクリアランスを超える計画は、管理者を含め、その呼び出し元にとって、一覧、件数、合計、検索結果、フィード、エクスポートのどこにも現れない | 呼び出し元が読めない計画の存在、名前、件数、合計を漏らすルート。「隠れている」と「存在しない」で異なるエラーメッセージやタイミング |
| ブレークグラス | 資格のある人のみ、理由の記載、最大四時間、第二の人への通知 | 資格なしでの使用。付与の延長。第二の人に通知されないままの操作 |
| 凍結された記録と追記専用の記録 | 監査証跡、発行済みのディレクターパック、実行の確信度の履歴、プログラムのステータス履歴、プロジェクトのバッファは、データベースで変更と削除を拒否する | API、一括取り込み、同じ行に触れるあらゆるルートを通じた更新や削除 |
| 職務分掌 | 要求者は自分の変更要求を承認できない | 要求者として、管理者として、提出後に承認者を変更して承認すること |
| アップロードと添付ファイル | 内容は宣言された種類と一致する必要がある。プログラムは拒否される。任意のウイルススキャンのフックは失敗時に閉じる | ポリグロットファイル、名前を変えたプログラム、過大なファイルや不正な形式のファイル、名前内のパスのトリック、スキャナーが本当に呼ばれているか |
| 送信リクエスト | ユーザーが指定する送信先は、公開 `https` アドレスに限定される | プライベート、リンクローカル、メタデータのアドレスへのサーバー側リクエストフォージェリ、リダイレクト、DNS リバインディング |
| セッションとブラウザー | アイドルタイムアウト、絶対的な上限、`httpOnly` クッキー、厳格な Content Security Policy、CORS の許可リスト | セッション固定と再利用、クロスサイトリクエストフォージェリ、インターフェースへのインジェクション、クリックジャッキング |
| レート制限 | 呼び出し元ごとの制限 | アイデンティティ、ヘッダー、パスを変えた回避。プロキシを挟んでも制限が保たれるか |
| データ主体ツール | エクスポートと仮名化。管理者のみ、事前にプレビュー | 管理者以外による使用。[個人データ一覧](../../../../governance/personal-data-inventory.csv)に対する網羅性 |
| バックアップ | 任意の暗号化、検証済みの復元 | バックアップファイルと鍵へのアクセス。クリーンな環境への復元 |

## プロジェクトが提供するもの

- ソース、仕様、テスト。コードレビューを主張から始められます。
- API の機械可読な記述（`/api-docs/openapi.json`）。ディレクターパックの作業についてはリクエストとレスポンスのスキーマ付きで、ルートの一覧はテストによってコードと照合されます。
- ログインを無効にした使い捨ての設定（`dev-insecure`、[README](../../../../README.md) を参照）。**テスト担当者自身のマシン専用**です。また、テスト用の鍵セットを生成するスクリプト（`scripts/smoke-keys.sh`）があり、テスト用の導入に対して、選んだ属性を持つトークンを発行できます。
- [データフロー図](../../../../governance/data-flow.md)、[ランブック](../../../../operations/runbook.md)、[復旧目標](../../../../operations/recovery-objectives.md)。
- 発見したことを報告するための非公開の経路: [SECURITY.md](../../../../SECURITY.md)。

## 交戦規則

テストの前に、書面でこれらを合意してください。プロジェクトは、あなたの環境に対してこれらを定められません。

- **環境。**現実的だが本物ではないデータを入れたコピーをテストします。書面で決めた場合を除き、本番はテストしません。
- **権限。**テスト担当者は、あなたの書面による許可、指名された連絡先、定められた時間帯を持ちます。
- **対象外。**物量によるサービス拒否、従業員へのソーシャルエンジニアリング、第三者のサービス（あなたのアイデンティティプロバイダーやホスト）は、それぞれの所有者が同意しない限り対象外です。プロジェクト自身の範囲は [SECURITY](../../../../SECURITY.md) にあります。
- **データ。**実際の個人データは使わず、持ち出さず、報告書にも載せません。
- **鍵。**テスト用の鍵は本番の鍵とは別で、終了後に破棄します。

## 報告と再テスト

- このソフトウェアに関する発見は、[SECURITY](../../../../SECURITY.md) にあるとおり、再現方法、バージョンまたはコミット、影響を添えて、メンテナーに非公開で送ります。プロジェクトの目標は、営業日 5 日以内の受領確認と 15 日以内の計画であり、保証ではありません。メンテナーは一人で、サービスレベル契約はありません。
- あなたの導入に関する発見は、あなた自身のオーナーに送ります。
- テスト担当者に、各発見の評価、**テストしなかった**ことの明示、修正の再テストを依頼してください。見つけたことだけを列挙する報告書では、見逃したことがわかりません。
- 報告書、範囲、日付、再テストは、あなた自身の記録とともに保管してください。プロジェクトはあなたに代わって保管できません。

## この文書の限界

これは対象とすべき領域を列挙したものであり、完全なテスト計画ではなく、表の主張はプロジェクト自身のものです。何も認証せず、問題のないテスト結果は、ある日付の一つの導入についての証拠にすぎません。

## あなたが決めること

誰が、いつ、何に対して、どのデータで、どのルールの下でテストするか、発見をどう評価し、いつまでに修正しなければならないか、そして結果を評価者と共有するかどうか。
