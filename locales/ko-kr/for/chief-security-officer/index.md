# 최고보안책임자(CSO)를 위한 안내

*최고보안책임자: 소프트웨어가 시행하는 것, 프로젝트가 검증한 것, 직접 테스트하고 운영해야 하는 것.*

## 소프트웨어가 시행하는 것

| 영역 | 동작 |
|---|---|
| 인증 | 로그인은 기본으로 켜져 있습니다. 서비스는 토큰 검증 키가 없으면 시작하지 않으며, 운영 환경에서 로그인이 꺼져 있어도 시작하지 않습니다. Microsoft Entra ID 같은 ID 공급자를 통해 로그인하며, 다중 인증은 공급자가 맡습니다 ([로그인 안내](../../../../operations/sign-in-with-entra.md)) |
| 권한 부여 | 토큰 속성에 대한 속성 기반 정책. 비공개 계획은 모든 사용자에게 모든 집계에서 제외되고, 취급 표시는 호출자의 허가 수준을 넘는 계획을 관리자까지 포함해 숨깁니다 |
| 긴급 접근 | 비공개 계획에 접근하려면 자격, 명시된 사유가 필요하며 최대 네 시간이고, 두 번째 사람에게 알립니다. 모든 요청이 감사됩니다 |
| 세션 | 유휴 만료(기본 30분)와 절대 세션 한도 |
| 전송과 브라우저 | 보안 헤더, 엄격한 콘텐츠 보안 정책, CORS 허용 목록, 호출자별 요청 속도 제한 |
| 외부 연결 | 사용자가 지정한 대상은 공개 `https` 주소로 제한됩니다 |
| 업로드 | 내용은 선언된 유형과 일치해야 하고, 프로그램은 거부되며, 선택 사항인 `clamd` 검사는 실패 시 차단합니다 |
| 감사 | 감사 추적은 데이터베이스에서 변경과 삭제를 거부합니다 |
| 고정된 기록 | 발행된 이사 패킷과 수행 신뢰도 평가는 데이터베이스 트리거로 변경할 수 없거나 추가만 가능합니다 |
| 공급망 | `cargo deny`, 소프트웨어 자재 명세서, 릴리스의 빌드 출처 증명, [보안 정책](../../../../SECURITY.md) |

## 수행되지 않은 것

- 침투 테스트, 제3자 감사, 독립 코드 검토, 인증이 없습니다.
- 악성코드 검사기가 포함되어 있지 않습니다. `clamd` 연결 지점은 대역으로만 시험했습니다.
- 데이터베이스 관리자가 감사 추적을 무력화할 수 있으며, 해시 체인은 없습니다.
- 취급 표시는 숨기고 표시할 뿐 암호화하지 않으며, 표시는 생성된 파일에 찍히지 않습니다.
- Redis를 설정하지 않으면 세션은 메모리에 보관됩니다.
- 정보 주체 도구는 참조를 찾을 뿐, 자유 텍스트, 업로드된 파일, 백업에 입력된 이름은 찾지 못합니다.

## 운영

백업에는 검증된 복원, 선택적 암호화, 명시된 복구 목표가 있습니다([운영 패킷](../../../../operations/README.md)). [운영 지침서](../../../../operations/runbook.md)는 기술적인 사고 대응 단계를 안내하며, 사고와 침해 대응 절차는 직접 마련해야 합니다. 취약점은 [SECURITY.md](../../../../SECURITY.md)가 설명하는 대로 비공개로 신고하세요. 목표는 영업일 5일 이내 접수 확인이며, 보장은 아닙니다.

## 직접 내려야 할 결정

누가 언제 침투 테스트를 수행하는지, ID 공급자의 조건부 접근과 역할 매핑, 이 배포가 보증받은 표시 수준, 첨부 파일 연결 지점 뒤의 검사기, 접근 권한을 얼마나 자주 재인증하는지.
