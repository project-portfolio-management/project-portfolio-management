# 致營運長

*營運長：您日常管理的事務、軟體為交付所做的事，以及執行它需要什麼。*

## 它為運營做什麼

- **交付計劃與控制：** 計劃、任務、依賴關係、關鍵路徑計算、跨計劃的里程碑、迭代與階段、燃盡圖和流動指標。
- **產能：** 分配、可用性、休假與非工作時段、資源角色，以及推匯出的工作量和利用率。（面向董事簡報包、按技能池和月份劃分的產能熱力圖尚未構建：`DP-10`。）
- **工時與成本：** 工時表、已記錄的工時、成本費率（限財務檢視）、預算和推匯出的成本。
- **治理流程：** 問題登記冊、帶職責分離的變更請求（提出者不能批准）、審批、評審、入職/調動/離職案例。
- **例外：** 紅色或琥珀紅的交付信心會開啟一個例外，須在 48 小時內（視窗可配置，1 至 720 小時）給出原因、所需的決定、具名負責人和決定截止日期。違約顯示在董事簡報包和 `GET /api/exceptions` 中。

## 執行它需要什麼

| 需要 | 詳情 |
|---|---|
| 服務 | 一個 Rust 服務、PostgreSQL 18、可選的 Redis（生產快取、可選的共享會話）、一個 SvelteKit 介面 |
| 執行手冊 | [運維包](../../../../operations/README.md)：部署、執行手冊、備份與恢復、恢復目標、升級與遷移 |
| 定時任務 | 沒有任何任務會自行排程。保留期清理、例外違約通知等任務須由您的運維人員放入排程器 |
| 支援 | 一位維護者，沒有服務水平協議；請自行預算一線支援 |

## 瞭解其侷限

- 數千個任務的計劃排程較慢；超過 5,000 個任務時，完整結果會被拒絕，除非明確請求（`?full=true` 或 `?only=critical`）。資料和注意事項見 [`BENCHMARKS.md`](../../../../BENCHMARKS.md)；它們只是來自一臺機器的數量級，不代表容量。
- 工作區的大部分有介面，但變更請求、問題、簡報包和交付信心**尚無**介面；目前只能透過 API 使用。

## 屬於您的決定

每個例外由誰負責，誰簽發月度簡報包（節奏與提醒屬於 `DP-12`，尚未構建），以及例外規則支撐怎樣的評審週期。
