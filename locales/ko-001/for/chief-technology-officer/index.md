# 최고기술책임자(CTO)를 위한 안내

*최고기술책임자: 아키텍처, 품질, 확장 방법, 그리고 엔지니어링이 얇은 곳.*

## 아키텍처

세 개의 하위 프로젝트, 하나의 엔터티([아키텍처](../../../../spec/08-architecture.md)):

| 부분 | 기술 |
|---|---|
| 일치 탐지 라이브러리 | Rust. 결정적이고 확률적이며 설명 가능한 쌍별 일치 탐지. 서비스에 내장됨 |
| 서비스 | Rust, axum 위의 axa, sqlx, PostgreSQL 18. `/api` 아래의 REST, 경로에서 파생된 OpenAPI |
| UI | SvelteKit 3, 프런트엔드용 백엔드를 갖춘 Svelte 5 SPA. i18n 카탈로그 |

툴체인은 [`rust-toolchain.toml`](../../../../rust-toolchain.toml)에 고정되어 있습니다. 영속성은 [명세 10](../../../../spec/10-persistence.md)에, API는 [명세 09](../../../../spec/09-api-surface.md)에 있습니다.

## 알아 둘 만한 엔지니어링 강점

- **불변 조건은 중요한 곳에서 데이터베이스에 있습니다.** 감사 로그는 변경과 삭제를 거부하고, 발행된 이사 패킷과 수행 신뢰도 평가는 트리거로 변경할 수 없거나 추가만 가능하며, CHECK 제약 조건이 서비스 규칙을 뒷받침합니다.
- **방어 테스트:** 새 집계 경로가 비공개 계획 필터를 건너뛰거나, 목록 경로에 페이지 나누기가 없거나, 개인정보 열이 목록에서 빠지거나, 경로가 OpenAPI에서 빠지면 전수 테스트가 빌드를 실패시킵니다. 테스트를 약화하는 것이 아니라 새로운 것을 분류해서 고칩니다.
- **실제 토큰 테스트:** 권한 부여는 서명된 PASETO 토큰으로 처음부터 끝까지 테스트됩니다(인증 설정은 프로세스마다 한 번 읽히므로 각 테스트는 자체 프로세스에서 실행).
- **공급망:** `cargo deny`, 소프트웨어 자재 명세서, 릴리스의 빌드 출처 증명, 보안 정책.
- **CI**는 푸시마다 모든 것을 빌드하고 테스트합니다. `.github/workflows/`를 보세요.

## 얇은 곳

- 유지 관리자 한 명이므로 버스 팩터는 하나입니다([`MAINTAINERS.md`](../../../../MAINTAINERS.md)).
- 성능은 대략만 알려져 있습니다. 응답 캐시는 주경로 경로만 다루며, 매우 큰 계획은 느립니다.
- Redis를 설정하지 않으면 세션은 메모리에 있습니다.
- 이사 패킷의 여러 항목과 모든 패킷 화면이 만들어지지 않았습니다([`tasks.md`](../../../../tasks.md)).
- 개발에 AI 도구를 사용했으며 제품에는 모델이 없습니다. [AI 성명](../../../../AI_STATEMENT.md)을 보세요.

## 직접 내려야 할 결정

호스팅과 Redis 토폴로지, 포크할지 업스트림을 따를지, 누가 코드를 독립적으로 검토하는지, 서비스가 ID 공급자와 어떻게 맞물리는지(PASETO 키 세트, 또는 Keycloak이나 Entra를 통한 OIDC).
