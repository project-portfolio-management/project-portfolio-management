# 最高情報責任者（CIO）向け

*最高情報責任者: 連携、アイデンティティ、データ、ホスティング、そして提出を求められる情報。*

## アイデンティティとアクセス

- ログインは**初期状態で強制**されます。トークン検証キーがなければサービスは起動を拒否し、本番でログインが無効の場合も拒否します。
- アイデンティティプロバイダー（Microsoft Entra ID を含む）によるサインイン。多要素認証はプロバイダー側で行います（[サインインガイド](../../../../operations/sign-in-with-entra.md)）。
- 認可は、トークンの属性（例: `access`、`directorpack`、`confidence`）と属性ポリシーを使います。非公開の計画はすべての集計から隠され、取り扱い区分により、呼び出し元のクリアランスを超える計画は管理者に対しても隠されます。
- 非公開の計画へのブレークグラスアクセスには、資格、理由の記載、最大四時間の制限、そして第二の人への通知が必要です。
- 管理者は、現行のアクセス付与を一覧でき（再認証の補助）、一人分のデータをエクスポートまたは仮名化できます。

## データと連携

| 項目 | 現状 |
|---|---|
| 保持するデータ | 計画、タスク、リスク、予算、マイルストーン、時間、コストの記録。人は氏名ではなく不透明な参照として扱われます。設計上、患者データも特別カテゴリのデータもありません |
| 一覧 | 個人データを保持する列はすべて[個人データ一覧](../../../../governance/personal-data-inventory.csv)に挙げられており、テストがスキーマとの一致を保ちます |
| インターフェース | 派生した OpenAPI ドキュメント付きの REST、一括の取り込みと書き出し、カレンダーフィード、公開 `https` の宛先のみへの送信イベントと webhook |
| バックアップ | スクリプトによるバックアップと検証済みの復元、任意の暗号化、明記した復旧目標（[バックアップと復元](../../../../operations/backup-and-restore.md)） |
| ホスティング | コンテナイメージと `compose.yaml`。ソフトウェア自身は転送を行わないため、データの所在はホスティングの選択次第です |

## 埋めるべきギャップ

- ペネトレーションテスト、独立したコードレビュー、認証: いずれも未実施です。
- 保持は部分的にしか強制されません。パージはスケジュールする必要があります（[保持スケジュール](../../../../governance/retention-schedule.md)を参照）。
- データ主体ツールが見つけるのは参照であり、自由記述やアップロードされたファイルに入力された氏名ではありません。
- 監査証跡は、データベース管理者に対して改ざん防止になっていません。
