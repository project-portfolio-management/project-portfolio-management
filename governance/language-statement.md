Which languages the interface is available in, how complete each one is, and what is
not translated. A buyer publishes this with their own contact details; the facts below
are what the software does today and are checked by tests where a test can check them.

path segment of every address (`/cy-001/plans`), so a link keeps its language. English is
used for any text that has no translation in the chosen language. Right-to-left layout is
supported (Arabic).

## What "every page in every language" means here

- All text that a page or a component prints is in a catalogue, not in the page. Two tests
  guard this and run in CI:
  - `tests/unit/catalogue-coverage.test.ts` fails when a template carries literal English
    words outside the catalogue, when the Welsh catalogue lacks a key or a `{placeholder}`
    the English has, or when a Welsh string is simply the English copied (except the short
    allow-list of words that are the same in both languages, such as names and units). The same
    checks run for every other locale's page catalogue.
  - `tests/e2e/welsh.spec.ts` opens **every page route** in English and in Welsh and fails
    when a line of visible text is identical in both and is not data or a name;
    `tests/e2e/every-locale.spec.ts` does the same for every supported locale.
- Dates, numbers and currency amounts use the conventions of the chosen locale.
- Words that the service sends as codes (a task status, a kind of plan, a proposal status)
  are shown through the catalogue, not as the code.

## What is not translated

- **Sentences generated by the API** (a validation message, a reason for a refusal) are
  English. The common error codes (`unauthorized`, `forbidden`, not found, internal error,
  rate limited) are translated by the interface; any other text the service sends is shown
  as sent.
- **Your own data** (plan names, task titles, notes, documents, announcements) is shown in
  the language it was written in. The model records the language of a work item
  (`in_language`); the interface does not translate it.
- **Operator documentation** in this repository is in English.
- **Exports** (CSV, evidence packs) keep their English column names so that they can be
  read by other tools.

## Statutory language duties

Several countries set duties on the language of a public service: for example the Welsh Language Standards in Wales,
the Official Languages Act in Canada and Québec's Charter of the French Language, the official-languages rules of
India's union and states, and the language laws of several European and Asian countries (named from general
knowledge, not checked against each law). Whether a deployment must meet one is for the buyer to decide. This
software provides the mechanism for each supported language alike: a complete interface, the language in the
address, and a review record waiting for its reviewer. It does not make a buyer compliant by itself. The review record
and the choice of wording for the buyer's own terms, in each language, belong to the buyer.

## How to ask for a correction

Send the key (from the review file) and the wording you would use to the contact named in
your published copy of this statement. Corrections change the
language's page catalogue (`src/lib/i18n-pages.<cy|ar|de|es|fr|hi|zh>.ts`) or its block of `src/lib/i18n.svelte.ts`;
the export script then refreshes the review file without losing recorded verdicts. Each record says how.
