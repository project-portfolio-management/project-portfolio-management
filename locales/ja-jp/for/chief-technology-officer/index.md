# 最高技術責任者（CTO）向け

*最高技術責任者: アーキテクチャ、品質、拡張の方法、そしてエンジニアリングが手薄な部分。*

## アーキテクチャ

三つのサブプロジェクト、一つのエンティティ（[アーキテクチャ](../../../../spec/08-architecture.md)）:

| 部品 | 技術 |
|---|---|
| マッチャーライブラリ | Rust。決定論的および確率的で、説明可能なペアごとの照合。サービスに組み込み |
| サービス | Rust、axum 上の axa、sqlx、PostgreSQL 18。`/api` 配下の REST と、ルートから導出される OpenAPI |
| UI | SvelteKit 3、Backend-for-Frontend 付きの Svelte 5 SPA。i18n カタログ |

ツールチェーンは [`rust-toolchain.toml`](../../../../rust-toolchain.toml) で固定されています。永続化は[仕様 10](../../../../spec/10-persistence.md)、API は[仕様 09](../../../../spec/09-api-surface.md) にあります。

## 知っておく価値のあるエンジニアリング上の強み

- **不変条件は、重要な場所ではデータベースに置かれます。**監査ログは変更と削除を拒否し、発行済みのディレクターパックと実行の確信度の評価は、トリガーにより不変または追記専用です。CHECK 制約がサービスのルールを裏付けます。
- **ガードテスト:** 網羅性テストは、新しい集計ルートが非公開計画のフィルターを飛ばしたとき、一覧ルートにページングがないとき、個人データの列が一覧から漏れているとき、ルートが OpenAPI から漏れているときに、ビルドを失敗させます。修正は、テストを弱めるのではなく、新しいものを分類して行います。
- **実トークンのテスト:** 認可は、署名された PASETO トークンでエンドツーエンドにテストされます（認証設定はプロセスごとに一度だけ読まれるため、各テストは専用のプロセスで動きます）。
- **サプライチェーン:** `cargo deny`、ソフトウェア部品表、リリース時のビルド来歴、セキュリティポリシー。
- **CI** はプッシュのたびにすべてをビルドしてテストします。`.github/workflows/` を参照してください。

## 手薄な部分

- メンテナーは一人で、バスファクターは一です（[`MAINTAINERS.md`](../../../../MAINTAINERS.md)）。
- 性能はおおよそしかわかっていません。レスポンスキャッシュはクリティカルパスのルートだけを対象とし、非常に大きな計画は遅くなります。
- Redis を設定しない限り、セッションはメモリ上にあります。
- ディレクターパックのいくつかのセクションと、パックの画面はすべて未実装です（[`tasks.md`](../../../../tasks.md)）。
- 構築には AI ツールが使われていますが、製品にモデルは含まれません。[AI に関する声明](../../../../AI_STATEMENT.md)を参照してください。

## あなたが決めること

ホスティングと Redis の構成、フォークするか上流を採用するか、誰が独立してコードをレビューするか、そしてサービスがあなたのアイデンティティプロバイダーにどう適合するか（PASETO の鍵セット、または Keycloak や Entra 経由の OIDC）。
