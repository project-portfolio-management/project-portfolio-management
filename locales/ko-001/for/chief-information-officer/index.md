# 최고정보책임자(CIO)를 위한 안내

*최고정보책임자: 통합, ID, 데이터, 호스팅, 그리고 제출을 요구받게 될 정보.*

## ID와 접근

- 로그인은 **기본으로 강제됩니다.** 서비스는 토큰 검증 키가 없으면 시작을 거부하며, 운영 환경에서 로그인이 꺼져 있어도 거부합니다.
- ID 공급자(Microsoft Entra ID 포함)를 통한 로그인. 다중 인증은 공급자가 맡습니다 ([로그인 안내](../../../../operations/sign-in-with-entra.md)).
- 권한 부여는 토큰 속성(예: `access`, `directorpack`, `confidence`)과 속성 정책을 사용합니다. 비공개 계획은 모든 집계에서 숨겨지고, 취급 표시는 호출자의 허가 수준을 넘는 계획을 관리자까지 포함해 숨깁니다.
- 비공개 계획에 대한 긴급 접근에는 자격, 명시된 사유가 필요하며 최대 네 시간이고, 두 번째 사람에게 알립니다.
- 관리자는 상시 접근 권한 목록(재인증 보조 수단)을 조회하고 한 사람의 데이터를 내보내거나 가명 처리할 수 있습니다.

## 데이터와 통합

| 주제 | 입장 |
|---|---|
| 보유 데이터 | 계획, 작업, 위험, 예산, 마일스톤, 시간, 비용 기록. 사람은 이름이 아니라 불투명한 참조입니다. 설계상 환자 데이터도 특수 범주 데이터도 없습니다 |
| 목록 | 개인정보를 담을 수 있는 모든 열이 [개인정보 목록](../../../../governance/personal-data-inventory.csv)에 나열되며, 테스트가 스키마와 일치하도록 유지합니다 |
| 인터페이스 | 파생된 OpenAPI 문서를 갖춘 REST, 대량 가져오기와 내보내기, 달력 피드, 공개 `https` 대상으로만 나가는 이벤트와 웹훅 |
| 백업 | 검증된 복원을 갖춘 스크립트 백업, 선택적 암호화, 명시된 복구 목표 ([백업과 복원](../../../../operations/backup-and-restore.md)) |
| 호스팅 | 컨테이너 이미지와 `compose.yaml`. 소프트웨어는 스스로 어떤 전송도 하지 않으므로 데이터 위치는 호스팅 선택에 달려 있습니다 |

## 메워야 할 공백

- 침투 테스트, 독립 코드 검토, 인증: 모두 수행되지 않았습니다.
- 보존은 일부만 시행됩니다. 삭제 작업을 예약해야 합니다 ([보존 일정](../../../../governance/retention-schedule.md) 참고).
- 정보 주체 도구는 참조를 찾을 뿐, 자유 텍스트나 업로드된 파일에 입력된 이름은 찾지 못합니다.
- 감사 추적은 데이터베이스 관리자에 대해서는 변조 방지가 되지 않습니다.
