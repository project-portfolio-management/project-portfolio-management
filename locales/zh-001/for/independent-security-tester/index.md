# 独立安全测试

*写给买方、评估人员或测试人员：对本软件进行独立安全测试应涵盖什么、项目提供哪些帮助、哪些已做哪些未做，以及哪些留给您。这是指导，不是测试报告，也不是法律意见。*

## 现状

**尚未进行任何独立安全测试。** 本软件没有渗透测试、第三方审计、独立代码评审或认证，项目也不声称有（[生产就绪度](../../../../governance/production-readiness.md)、[SECURITY](../../../../SECURITY.md)）。项目的持续集成中运行被动扫描（规则在 `.zap/rules.tsv`），项目自己的测试检查下文列出的控制；二者都不能代替一位没有编写过这个软件的测试人员。

这是[保证清单](../../../../governance/assurance-checklist.md)的第 1 项和第 9 项。它属于部署方，由持证测试人员针对**您的**部署进行：项目无法测试您的托管、身份提供方、网络或密钥。

## 测试什么

按实际运行的方式测试部署，强制登录，并让您的身份提供方位于前端。根据软件所声称的控制，建议的范围如下：

| 领域 | 软件声称的 | 测试人员应尝试的 |
|---|---|---|
| 认证 | 默认启用登录；没有验证密钥服务不会启动，在生产环境中关闭登录也不会启动；令牌用公布的密钥离线验证 | 伪造、过期、重放和签名错误的令牌；错误的签发者或受众；密钥轮换；缺失密钥集 |
| 授权 | 基于属性的策略；记录级规则 | 每个路由上的横向和纵向越权；更改路径和请求体中的标识符；调用者不应能添加的属性 |
| 私有计划与处理标记 | 私有计划以及高于调用者许可级别的计划，不出现在该调用者的任何列表、计数、合计、搜索结果、订阅源或导出中，管理员也不例外 | 任何泄露调用者无权读取的计划的存在、名称、计数或合计的路由；“被隐藏”与“不存在”之间不同的错误信息和响应时间 |
| 紧急通道 | 仅限符合资格者、陈述理由、最长四小时、通知第二个人 | 无资格使用；延长授权；未通知第二个人就行动 |
| 冻结与只追加的记录 | 审计记录、已签发的董事简报包、交付信心历史、项目集状态历史和项目缓冲在数据库中拒绝更改和删除 | 通过 API、批量导入以及任何涉及同一行的路由进行更新或删除 |
| 职责分离 | 请求者不能批准自己的变更请求 | 以请求者身份、以管理员身份批准，以及提交后更换批准人 |
| 上传与附件 | 内容必须与声明的类型一致；程序被拒绝；可选的病毒扫描钩子在失败时拒绝放行 | 多语言混合文件、改名的程序、超大和畸形文件、名称中的路径技巧，以及您的扫描器是否真被调用 |
| 出站请求 | 用户提供的目的地仅限公共 `https` 地址 | 对私有、链路本地和元数据地址的服务端请求伪造、重定向、DNS 重绑定 |
| 会话与浏览器 | 空闲超时、硬性上限、`httpOnly` Cookie、严格的内容安全策略、CORS 允许列表 | 会话固定与重用、跨站请求伪造、向界面注入、点击劫持 |
| 速率限制 | 按调用者限制 | 通过更改身份、标头或路径绕过；限制能否在您的代理之后依然有效 |
| 数据主体工具 | 导出与假名化，仅限管理员，先预览 | 非管理员使用；对照[个人数据清单](../../../../governance/personal-data-inventory.csv)检查完整性 |
| 备份 | 可选加密，经过测试的恢复 | 访问备份文件和密钥；恢复到干净的环境 |

## 项目提供什么

- 源代码、规范和测试，使代码评审可以从这些声明出发。
- 机器可读的 API 描述（`/api-docs/openapi.json`），包含董事简报包相关工作的请求与响应模式；路由列表由测试与代码核对。
- 登录关闭的一次性配置（`dev-insecure`，见 [README](../../../../README.md)），**仅限测试人员自己的机器**，以及一个生成测试密钥集的脚本（`scripts/smoke-keys.sh`），以便针对测试部署签发带指定属性的令牌。
- [数据流图](../../../../governance/data-flow.md)、[运行手册](../../../../operations/runbook.md)和[恢复目标](../../../../operations/recovery-objectives.md)。
- 报告发现的私下渠道：[SECURITY.md](../../../../SECURITY.md)。

## 交战规则

测试前以书面形式商定这些；项目无法为您的环境设定它们。

- **环境。** 测试一份副本，使用逼真但非真实的数据。除非您已书面决定，否则不要测试生产环境。
- **授权。** 测试人员持有您的书面许可、一位指定联系人和明确的时间窗口。
- **范围之外。** 靠流量的拒绝服务、对员工的社会工程学以及第三方服务（您的身份提供方、您的主机）不在范围内，除非各自的所有者同意。项目自身的范围见 [SECURITY](../../../../SECURITY.md)。
- **数据。** 不使用真实个人数据，不将其复制出去，也不写入报告。
- **密钥。** 测试密钥与生产密钥分开，并在事后销毁。

## 报告与复测

- 关于本软件的发现应按 [SECURITY](../../../../SECURITY.md) 所述私下提交给维护者，附上复现方法、版本或提交以及影响。项目的目标是 5 个工作日内确认、15 个工作日内给出计划；这是目标，不是保证。只有一位维护者，没有服务水平协议。
- 关于您的部署的发现交给您自己的负责人。
- 请测试人员对每项发现评级，说明**未**测试的内容，并对修复进行复测。只列出发现内容的报告无法告诉您遗漏了什么。
- 将报告、范围、日期和复测与您自己的记录一起保存。项目无法替您保存。

## 本文档的局限

它列出需要涵盖的领域，不是完整的测试计划，表中的声明是项目自己的。它不证明任何事情，一次干净的测试只是关于某一部署在某一日期的证据。

## 属于您的决定

谁来测试、何时、针对什么、用什么数据、在什么规则下；如何给发现评级、必须在何时之前修复；以及结果是否与您的评估人员共享。
