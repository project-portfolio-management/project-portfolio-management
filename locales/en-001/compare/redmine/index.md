# Project Portfolio Management and Redmine

*Configure everything, or start with a fixed vocabulary?*

**How this page was written.** Nobody installed or ran Redmine for this comparison. Its description is general, and it may be out of date, so please check Redmine's own documentation. Different products solve different problems, so nothing here is scored. The facts about this project come from its own repository.

## What Redmine is

A long-established, configurable, open-source project tracker where the organization defines issue types, statuses, custom fields and roles.

## Redmine may suit you better if

- You want to define your own issue types and workflow for each type
- You want a long production history and a large plugin ecosystem

## This project may suit you better if

- You want a vocabulary that is ready to use: custom fields exist here, but there is no per-type workflow matrix
- You need portfolio views, critical path, earned value and governance
- You need explainable duplicate matching

## Moving your work

There is **no Redmine importer**. This project took ideas from Redmine, not code: custom fields, per-plan modules, watchers and approvals.

## Before you decide

This project is young, with one maintainer and no third-party audit. Its own verdict is that it is ready for a controlled pilot on non-clinical, non-secret data, and not ready for unsupervised production use. It has no mobile app and no real-time co-editing. Read [where it is behind](../../topics/comparisons/index.md#where-it-is-behind).
