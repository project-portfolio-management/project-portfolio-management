# 운영 환경으로 가는 길

*이 소프트웨어에서 "운영 환경"이 무엇을 뜻하는지, 그리고 항목별로 얼마나 떨어져 있는지.*

여기서 "운영 환경"이란 조직이 실제 업무를 위해 소프트웨어를 운영한다는 뜻입니다. 실제 계획, 실제 사람의 이름, 실제 결정이 여기에 달려 있고, 장애나 유출은 결과를 낳으며, 누군가가 책임을 집니다. 대형 보건 기관이나 정부 부처에서는 운영 환경이란 조직 자체의 보증 절차를 통과했다는 뜻이기도 합니다. 보안 테스트, 데이터 보호 영향 평가, 접근성 감사, 그리고 영국 국민보건서비스(NHS)에서는 디지털 기술 평가 기준(DTAC)이 그 예입니다.

## 현재 위치

- 인증, 승인, 감사를 받았다고 주장하지 않습니다. 이 페이지는 프로젝트 자체의 추정입니다.
- "의료"는 **비임상** 포트폴리오 및 프로젝트 도구를 뜻합니다. 환자 기록도 임상 의사결정 지원도 없습니다.
- 프로젝트는 비임상, 비기밀 데이터로 시범 운영을 시작하되, 자체 보증을 완료하는 조직이 운영하기를 권합니다.

## 준비 상태, 항목별

각 수치는 2026년 11월 13일 기준 프로젝트의 추정이며 측정값이 아닙니다. 각 슬라이더는 그 추정값에서 시작합니다. 슬라이더를 움직이면 읽는 동안 자신의 견해가 기록될 뿐, 아무것도 저장되거나 전송되지 않습니다.

- **독립적인 보안 보증** — 0%. 침투 테스트도, 제3자 감사도, 인증도 없습니다. 구매자나 공급자가 의뢰해야 합니다 (RG-13).
- **접근성** — 40%. 자동화된 WCAG 2.2 AA 감사가 모든 변경마다 모든 경로에서 실행됩니다. 수동 테스트도, 보조 기술이나 장애인과 함께한 테스트도 하지 않았습니다 (RG-13).
- **정보 주체 요청** — 50%. 관리자는 스키마의 모든 참조에 걸쳐 한 사람을 내보내고 가명 처리할 수 있으며, 먼저 미리 보기가 나옵니다 (RG-6). 제목, 댓글, 문서에 입력된 이름, 업로드된 파일, 감사 스냅샷, 백업은 자동으로 찾지 못합니다.
- **보존** — 35%. 기본값이 시험 실행인 삭제 작업이 알림, 전달 로그, 멱등성 키, 추세 및 도입 스냅샷을 다루며, 기간은 배포마다 정합니다 (RG-4). 계획, 작업, 시간 기록, 문서, 감사 추적은 운영자가 삭제할 때까지 보관됩니다.
- **취급 표시** — 60%. 설정 가능한 분류 체계가 호출자의 허가 수준을 넘는 계획을 관리자까지 포함해 숨기고 모든 응답에 표시를 붙입니다 (RG-7). 표시는 생성된 파일에 찍히지 않으며, 허가는 ID 공급자의 속성만큼만 믿을 수 있습니다.
- **첨부 파일 안전** — 50%. 내용은 선언된 유형과 일치해야 하고, 프로그램은 거부되며, 선택 사항인 `clamd` 검사는 실패 시 차단합니다 (RG-8). 검사기는 포함되어 있지 않고, 연결 지점은 대역으로만 시험했습니다.
- **접근 검토와 비상 접근** — 45%. 상시 부여 권한 보고서가 재인증을 돕고 (RG-9), 비상 접근은 시간이 제한되며 명시된 사유가 필요합니다 (RG-10). 보고서는 기록된 내용을 보여 줄 뿐 ID 공급자가 시행하는 내용이 아니며, 검토자의 결정을 기록하는 경로가 없고, 비상 접근 알림이 아무것도 받지 못하는 사람을 지정할 수 있는데도 권한은 그대로 유효합니다.
- **성능과 용량** — 40%. 한 대의 기계에서 한 부하 및 장시간 시험이 [`BENCHMARKS.md`](../../../BENCHMARKS.md)에 있습니다. 일반 요청은 수십 밀리초 안에 응답하고, 약 12,700개 작업의 계획은 일정 계산이 느리며, 프로세스는 약 1GB까지 커집니다. 용량 계획도, 다수 사용자 시험도, 여러 기계에 걸친 실행도 없습니다.
- **여러 프런트엔드 서버에 걸친 세션** — 70%. Redis를 설정하지 않으면 세션은 메모리에 보관됩니다 (RG-12). Redis를 쓰면 로그인이 Redis에 의존합니다.
- **감사 추적 무결성** — 50%. 쓰기는 감사되고, 데이터베이스 트리거가 명시된 예외를 제외한 변경과 삭제를 거부합니다 (RG-3). 데이터베이스 관리자는 트리거를 제거할 수 있으며, 해시 체인은 없습니다.
- **백업과 복구** — 80%. 복원은 지속적 통합에서 평문과 암호화 상태 모두로, 명시된 복구 목표에 맞춰 시험됩니다 (RG-5). 암호화는 선택 사항이며, 훈련은 배포자의 호스팅이 아니라 프로젝트 자체 CI에서 실행됩니다.
- **지원과 연속성** — 10%. 유지 관리자 한 명, 서비스 수준 계약 없음 ([`GOVERNANCE.md`](../../../GOVERNANCE.md)).
- **번역** — 20%. 영어 이외 언어의 텍스트는 해당 언어 사용자가 검토하기 전까지 기계가 작성한 것이며, 법정 언어 의무에는 검토된 텍스트가 필요합니다 ([언어 성명](../../../governance/language-statement.md)).
- **임상 사용** — 0%. 임상 안전 사례가 작성되지 않았으며, 임상 사용은 범위 밖입니다.

## 첫 배포에서 할 일

1. [보증 체크리스트](../../../governance/assurance-checklist.md)를 완료합니다. 침투 테스트와 접근성 감사부터 시작하세요.
2. [DTAC 체크리스트](../../../governance/dtac-checklist.md)의 모든 "구매자 작성" 행과 [DPIA](../../../governance/dpia.md)의 표시를 채웁니다.
3. 기록 관리자와 보존 기간을 합의하고 삭제 작업을 예약합니다.
4. 암호화 백업을 켜고 배포 자체의 호스팅에서 복원 훈련을 실행합니다.
5. 데이터는 비임상으로 유지하고, 배포가 보증받은 표시 수준 이하로 둡니다.
6. 위의 공백에 대비하거나, 그것을 없앨 비용을 마련합니다.

각 항목의 근거는 [평가](../../../governance/production-readiness.md)에 있습니다.
